# V1 Qwen latency and command-session UX

Target: Firefly ROC-RK3588S-PC / RK3588S, RKLLM 1.3.0, existing Qwen3-4B W8A8,
Russian Zipformer/Silero and frozen Amina v3. Starting checkpoint:
`ae81a1b003d971ea5b52ebac52dc6ccfcd784764` (`v1-amina-wake`).

## Command contract and safety

Production `RuntimeModel` now selects `StableCompact`. Deterministic grounding
against the immutable generation selects **one device and one permitted action**.
Ambiguous targets/actions never reach the model. The model receives only that
selected contract (IDs, names, operation, exact argument type/range and output
shape) and the original text as JSON data. It neither chooses IDs nor sees a
transport/binding. Chat delimiters in data are escaped, including catalog metadata.

The compact ordered-argument codec is deliberately small:

| Selected schema | Allowed successful response | Unsupported |
| --- | --- | --- |
| One required integer | `[40]`, `[0]`, `[100]`, etc., within the configured range | `null` |
| No arguments (including entrance door) | `[]` | `null` |

`U` is also accepted solely as a rejection sentinel. Bare numbers, quoted numbers,
floats/exponents, leading zeroes, extra arguments, text, markdown, object IDs and
out-of-range values are rejected. Only surrounding ASCII whitespace is ignored.
There is no output/transcript repair. `CompactActionDecoder` supplies the selected
IDs and configured argument name to construct `GenericAction`. The unchanged
SafetyGate still checks the **original text**, followed by domain validation,
BindingResolver and HardwareExecutor. Door explicit-opening safeguards remain.

More complex schemas retain the existing strict structured JSON decoder, additionally
locked to the selected IDs. They may still require a scoped context. This preserves
configuration extensibility without pretending to implement an arbitrary tuple codec.
Legacy direct `CommandEngine` users and structured mock adapters retain the original
JSON default. Fast Path never calls either the model or the compact decoder.

An initially shorter bare-number / `A` / `U` protocol failed the DEV comparison
(19/26 versus 26/26 baseline). Further bare-scalar trials also failed. They were
not accepted. The ordered JSON argument tuple is slightly longer but keeps IDs out
of the response and restored 26/26 in development. Raw exploratory reports are kept
under `benchmarks/qwen-latency/experiments/`; these are not claimed as final speed
measurements. In particular the last exploratory array run overlapped compilation.
No training, quantization, sampling or model change was made.

## Stable context and resource limits

Startup initializes one model handle and bootstraps one generic command system
context. All supported V1 targets share it. Each request clears KV with keep-system,
sends its selected schema plus original text, and decodes against that same immutable
selection. Kitchen → Bedroom → Kitchen and light → door need no template refresh or
bootstrap. No dummy question, parallel model, persistent cache or full catalog is
used as inference state. The existing full catalog prompt remains a diagnostic
artifact only for this path.

Original input remains limited to 192 UTF-8 bytes. Trusted schema metadata is bounded
to 1024 bytes. Compact command envelopes permit at most 256 actual request tokens;
the original product/Admin request reservation remains 128. Actual runtime counts,
bootstrap + request + response budget, KV size and output termination are checked
against the unchanged 1024-token context and 128-token command response budget.
Failures reject the command and require existing runtime recovery; output is never
replayed after failure. Metadata is generated by C++, not accepted from model output.

Apply/preflight reuse the stable prompt for supported schemas and publish complete
generations transactionally. Admin Copilot retains its separate 256/384-token output
budgets and serialized use of the same handle. Entering/leaving an Admin context
still requires a genuine context refresh; its completion restores the command
context. Unsupported complex schemas also retain measured, bounded scoped admission.

## Reproducible measurements

The initial bare-scalar compact run preceded stable-context work. After the tuple
codec was selected, scoped compact was remeasured with that same codec for a
controlled comparison; the main intermediate column is this rerun of the old
context lifecycle. Its false rejection is retained, not counted as a success.

The JSON baseline was recorded **before output/context optimization**, using the
production generation/grounding/CommandEngine path with only timing instrumentation.
The corpus has 26 actual LLM_FALLBACK requests: four rooms, values 0..100, polite
on/off, unsupported/invalid requests and door commands, with repeated targets,
switches and switch-backs. No request executes hardware.

Per-request input, deterministic selection, raw output, expected/actual action,
correctness, context setup/bootstrap, prefill time/tokens, generation time/tokens,
inference wall time and total wall time are retained in JSON and CSV:

- [All measured tables](../benchmarks/qwen-latency/results.md)

Final measurements (means over the same 26 fallback requests):

Final total LLM wall time fell **71.4%** (3.49×), generation **82.7%**, and output
tokens **82.9%**. The tradeoff is explicit: per-request prefill rose from 403 to
1287 ms because the selected schema travels with each request. Same-target requests
are therefore slower than scoped compact's warm requests, but still much faster
than the JSON baseline; context switches no longer add ~5 seconds.

Scoped compact's one failure was a false rejection of “Будь добр выключи свет на
кухне”: `[]` does not match its one-integer schema, so it could not execute. The
final stable trusted request envelope produced the correct `[0]`. No incorrect
executable action occurred in any of the three measured stages. The explicit
Kitchen → Bedroom → Kitchen table is in the linked complete report.

Context setup includes template/KV operations and bootstrap; startup/model load is
separate. `total_llm_wall_ms` is setup plus synchronous inference, not STT, microphone
waiting, HTTP execution or startup. Vendor timings exclude some wrapper overhead.
Results describe this DEV corpus on this board, not a statistical accuracy guarantee
or p95 production latency claim.

## Wake, beep and split timing (original latency milestone)

```text
WAITING_WAKE                  PCM -> unchanged Amina KWS
  WAKE_DETECTED
  ACKNOWLEDGING_WAKE            PCM drain/discard; KWS and command VAD idle
  BEEP_START -> BEEP_END         native ALSA output, 100 ms
  250 ms capture/tail drain
  LISTENING_COMMAND             fresh VAD/history, wait ~5 s for speech start
    no speech -> COMMAND_START_TIMEOUT -> WAITING_WAKE
  CAPTURING_COMMAND             start deadline disabled; existing VAD endpoint
    excessive speech -> COMMAND_MAX_DURATION -> WAITING_WAKE
  SPEECH_END -> PROCESSING       STT -> command pipeline; capture drains/discards
  WAITING_WAKE                  fresh wake frontend/model/window
```

There is exactly one capture owner on XVF3800, S16_LE/16000/stereo/channel index 1.
Acknowledgement is an independent **playback** PCM on the board codec, not another
capture consumer. `WakeAcknowledgement` is poll-driven; `AlsaWakeAcknowledgement`
generates 1600 mono samples, 880 Hz, amplitude 0.12, 10 ms fades. It uses nonblocking
write/drain, a one-second completion guard and RAII close/drop. No per-wake shell,
`aplay`, extra worker or large WAV asset is needed. A fake implementation tests the
same lifecycle. Playback failure is observable as `ACKNOWLEDGEMENT_FAILED` and
`health.subsystems.acknowledgement=failed` (overall degraded); the already admitted
session may continue only with healthy capture/VAD/STT. It never bypasses wake.

| Setting | Default | Semantics |
| --- | --- | --- |
| `--command-start-timeout-ms` | 5000 (1000..15000) | wait for speech start, armed after beep/drain |
| `--command-listen-timeout-ms` | absent | deprecated explicit 1000..60000 total listening cap; preserves old behavior |
| `--playback-device` | `plughw:CARD=rockchipes8388,DEV=0` | native acknowledgement output |
| Segmenter maximum speech | 15000 ms | unchanged speech-length bound |
| Capture hard bound | maximum speech + 2000 ms | independent endpoint/post-roll/noise guard after speech confirmation |

The unchanged Silero detector requires 250 ms speech to confirm onset. Its public
API exposes confirmation, not tentative onset. A bounded 288 ms allowance is added
to the start deadline (one frame beyond the confirmation interval); thus silence
returns to wake after about 5.3 s, while speech begun around 4.8 s can be confirmed
and completed. This is deadline bookkeeping, not VAD threshold/model tuning. See
[the pinned sherpa implementation](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.7/sherpa-onnx/csrc/silero-vad-model.cc).
Fake detectors with immediate confirmation need no allowance and time out at 5 s.

State logs carry monotonic timestamps for wake, beep, listening arm, speech
confirmation/endpoint and processing. Voice results carry `stt_ms`,
`llm_context_ms`, `llm_prefill_ms`, `llm_generation_ms`, `llm_output_tokens`,
`processing_ms`, route and result. Admin diagnostics expose the same command metrics.
No per-frame logging is added. Shutdown cancels playback, joins processing and lets
existing capture/KWS/STT owners release their resources.

## Automated acceptance and limits

Run the deterministic/full suites and the explicit on-board checks serially:

```bash
ctest --test-dir build -R 'CompactActionDecoder|RkllmContextRefresh|WakeSessionUx|WakeVoiceGating|V1PrototypePipeline|Amina|HealthReliability|UnifiedHttp' --output-on-failure
ctest --test-dir build --output-on-failure
./build/alsa_acknowledgement_smoke
python3 tests/execution/WakeCompactReplay.py build/wake-compact-replay.json
python3 tests/execution/WakeCompactReplay.py --original-dev
```

`WakeCompactReplay` uses fake wake admission and acknowledgement, recorded DEV PCM,
real frozen VAD/Zipformer, the real compact Qwen runtime, unchanged safety/bindings
and the existing loopback V1 HTTP mock. It schedules late recorded speech, verifies
40 fallback/on/off/unsupported, checks three POSTs only, and returns to WAITING_WAKE.
For on/off the DEV clips lack a room: the harness composes their **PCM** with a
recorded “на кухне” prefix from the existing kitchen clip. There is no transcript
correction or synthesized STT result; original WAVs are untouched. This tests the
integration, not acoustic naturalness of the splice. The existing original replay
suite separately covers unmodified DEV recordings.

Physical speaker audibility remains a human UX smoke check, not a blocker for
automated open/write/drain/close verification. This milestone does not claim a new
human microphone acceptance or change the previously accepted Amina model. At that
checkpoint imperfect wake/command timing could include a wake remainder or lose an
early command prefix, and continuous “Амина включи…” was not supported reliably.
The seamless follow-up below addresses this with bounded history and scoped prefix
removal; its remaining boundaries are documented separately. Long reverberation beyond the drain guard is an acoustic limitation.
Existing synchronous vendor/STT hang limitations remain; no detached workers or
unsafe always-listening fallback are introduced.

### Recorded acceptance evidence

The [automated replay report](../benchmarks/qwen-latency/replay.json) records all four
successful checks. In each, listening armed at virtual 416 ms and VAD confirmed
speech at 5504 ms: **5088 ms after arming**, beyond the nominal five-second start
budget. The confirmation allowance admitted it; the command then reached its normal
endpoint. Event times in this harness are an injected PCM clock (not wall latency).
`stt_ms` and `processing_ms` are real elapsed measurements. Recorded prefix length
for the on/off PCM fixtures was 1000 ms.

The four transcripts were “на кухне поставь свет на сорок процентов” (LLM_FALLBACK),
“на кухне включи свет” and “на кухне выключи свет” (FAST_PATH), and “открой дверь”
(LLM_FALLBACK, SafetyGate REJECT). The last case deliberately exercises a real
model proposal that safety must reject: Qwen returned `[]`, but the original text
lacked an entrance reference. Exactly three mock requests carried 40, 100 and 0.
No physical light/door execution occurred. ALSA playback open/write/drain/close
also passed on `rockchipes8388`; audibility is not asserted.

The original DEV harness also passed **8/8 exact transcripts and actions, 2/2
silences**, plus a real Apply to generation 2 and a repeated kitchen-40 command.
Its fixture now supplies explicit loopback HTTP bindings and the required empty
`state` for its schema-v2 added light. Missing-room DEV on/off expect deterministic
grounding rejection; STT/runtime failures still fail the test. The run had one
`LLM_CONTEXT` bootstrap total, including Apply, and exactly five mock POSTs.

## Seamless invocation

The follow-up to checkpoint `0c76e0ead1c29c0ff1edd845a48f133bcec6f3c0`
supports “Амина” → pause → beep → command **and** “Амина, command…” → no beep.
Qwen model, compact protocol, stable warmed context, Fast Path, GenericAction,
SafetyGate, bindings and execution are unchanged; the benchmark numbers above
remain the historical Qwen comparison, not new performance claims.

One ALSA capture adds a bounded 3 s mono ASR ring. After KWS detection a 256 ms
continuation grace and paired probes of the existing Silero VAD distinguish new
speech from its residual state. A joined probe worker exclusively owns VAD while
the one capture loop buffers up to 1 s of post-detection PCM; overflow fails
closed. Only the inline path re-feeds real buffered PCM,
including command audio preceding detection, to fresh authoritative segmentation.
Probe-only virtual silence is discarded. Only a leading exact `амина`/confirmed
`афина` in this KWS-admitted inline transcript is removed before CommandEngine;
raw STT remains observable. No transcript normalization runs for text/Admin or
separated commands. Full [state/boundary details](v1-amina-wake.md#seamless-invocation)
and [measured overhead/validation](../benchmarks/seamless-wake/results.md).

The separated defaults remain 100 ms native beep + 250 ms drain, 5000 ms speech
start wait (+ bounded 288 ms VAD confirmation allowance), then ordinary endpoint
and the separate 15000 ms speech bound. The deprecated explicit total timeout
retains its cap after admission. Inline has no beep or start wait; it uses the
same max-speech guard and 17000 ms capture watchdog. No new UI/config sensitivity
control was introduced. Existing STT timing/acoustic limitations remain at pauses,
unknown wake-prefix spellings and the finite history boundary.

Live helper `./scripts/v1-wake-live.sh` prints both path checks and records
`CONTINUATION_INLINE` / `CONTINUATION_SEPARATED`, `inline`, `wake_prefix_removed`,
STT and command timing. Human live testing was not run for this follow-up.
