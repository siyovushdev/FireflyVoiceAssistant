# AI Setup: complete natural-language requests

AI Setup uses the existing local Qwen3-4B W8A8 Admin4096 model. It prepares a private draft. A user reviews the proposed configuration and explicitly applies it; planning does not execute devices.

## Input and context

The application accepts up to 12,000 Unicode code points / 48,000 UTF-8 bytes, including multiline pasted text. This is an input-storage limit, not a promise that every document fits the model context. There is no silent truncation. The existing compiled model context remains 4096 tokens, including instructions, relevant catalog, input and reserved answer.

The former 1800-byte V2 rejection is removed. A complete request is JSON-quoted as `INPUT_DATA` in each admitted Admin context. Chat delimiters are escaped. The user instruction is short and fixed, allowing more of the existing context to hold the document. Real RKLLM token counts and output guards still apply. The ordinary Admin request profile and Runtime1024 remain unchanged. A rejected context restores the previous valid context before a recoverable budget error is reported.

A request's final restrictions remain available to the planner; the UI does not split numbered lists, decimal values, IPv4 addresses or sentences into independent user requests. The legacy explicit stepping API remains for compatibility. The model response is bounded to 12 typed operations or compact `power_setup` groups. A group describes a new power device, its connection, both commands and optional readback once; the server expands it through the same validators, with a maximum of 64 internal operations (the existing six-zone/ten-device limits remain). A larger or unsupported plan requires clarification; a prefix must not be presented as complete. Explicit connection timeouts are preserved. Separated HTTP host/port values can form a numeric HTTP URL; no endpoint is guessed.

Admission is checked before persisting an incomplete checkpoint. A failed message can be explicitly discarded to its pre-message draft and edited. Crash recovery, owner/version checks, CAS and whole-message rollback remain authoritative. Progress and cooperative Cancel use the existing server session; a running synchronous model call may need to finish before cancellation restores Runtime.

## Connections

A natural-language request can create existing supported logical devices and explicit HTTP, MQTT, Modbus TCP and Modbus RTU connection/mapping/readback contracts. The server allocates IDs and resolves action/device/connection names. The model cannot invent network endpoints, topics, payloads, register addresses, Unit IDs, methods, paths or serial parameters. Missing facts require a question. Credentials are stored using the existing separate protected credentials form; a prompt can refer to an existing `credentials_id`.

Example:

> Создай кухню и свет, который можно включать и выключать. Подключение Брокер — MQTT, host 192.168.68.111, port 1883. Для включения topic home/kitchen/set и payload ON, для выключения тот же topic и payload OFF. QoS 0, retain false. Чтение topic home/kitchen/state, format text, field power, true_payload ON, false_payload OFF.

Specify credentials separately when needed. MQTT AI observations in this MVP use text payloads; configure JSON observations in the existing manual editor. For Modbus supply the zero-based protocol address, function, wire type, Unit ID and TCP endpoint or complete RTU parameters; see [the supported Modbus contract](modbus-connectivity.md). Generic raw TCP/UDP/CAN and arbitrary programmable automation remain unsupported.

## Evidence and limits

Strict schema/domain/grounding validation rejects invalid or unstated operations. Model self-report that a document is complete is not proof of perfect semantic coverage. Review remains necessary. CPU tests with forced model outputs test guards and transactions, not language quality. The opt-in `tests/admin/SetupRealModelTests.py` runs a local Qwen3-4B GGUF CPU backend through the production RuntimeWorker/document decoder to check qualitative examples. It is distinct from native W8A8 RKLLM, performance, resource and hardware acceptance.

The browser tests use the real C++ HttpServer and a private ConfigStore with a scripted inference seam. They cannot establish physical devices or real Qwen behavior. No inference request uses a cloud service.

Large connected-device creation requests use a short inventory followed by one typed device object per model call. Every call sees the complete original text, including all final restrictions. No independent sentence splitting or implicit application occurs. The combined plan goes through the same authoritative full-document validation; a later question or failure cannot expose a successful prefix. The native 384-token stages use existing 60-second context/inference watchdogs, share one format retry for the whole document, and reserve remaining session time before starting another stage. The one-pass 768-token document profile retains its finite 240-second watchdog. Neither path repairs malformed JSON or bypasses validation. Cancellation remains cooperative: the UI acknowledges it immediately, and Runtime restoration waits for the in-flight planning operation to return or abort. Optional language enrichment stops early when insufficient session time remains; the valid core plan and base speech forms are preserved with an explicit warning. A valid response is a proposal, not a guarantee that every natural-language request was understood perfectly. If inference fails, the original text remains available for editing or manual configuration.

## Development iteration

On 2026-11-08 the owner requested incremental development updates instead of a full release for each edit. For this cycle, build only the changed CMake targets, run the relevant Setup/document/API tests, then test the actual installed Admin model. An explicitly labelled development executable can run through a runtime systemd override of the existing service. Keep the immutable current release, libraries, models, workers and store intact; no old version needs reinstalling. Record the dirty source fingerprint and executable digest. This is not a finalized release or a replacement for final release acceptance. A runtime override is lost on reboot; remove only that owned override to return to the unchanged installed executable.

The mixed-protocol regression in `tests/admin/setup-mixed-document.json` is the exact 3987-character example that previously exceeded the 240-second generation deadline. CPU tests establish its compact decoder expansion and negative guards, not Qwen language quality. Native model measurements must be recorded separately. Timeout errors are now explained in Russian, without embedding a JSON error array in the user-facing message.

Compact new-device operations use named JSON objects (`op`, `zone`, `device`, `connection`, `commands`, `observation`); typed arrays remain accepted for compatibility. New connection names default to the user-supplied device name. A compact creation cannot overwrite an existing connection. Existing connections are referenced by name with their settings preserved. Longer device names take precedence only over overlapping occurrences: `Рабочая лампа` does not also select `Лампа`, while `Лампа и Рабочая лампа` still selects both.

An interrupted browser session retains its safe input text without retaining an invalid owner token. Resume and explicit retry still check the current server version and exact pending message; no retry or Apply is automatic.

Staged connected-device planning also checks each device against its explicitly named source section before continuing. The complete original input and final restrictions remain available; parameters from neighbouring devices are not evidence for the selected target. Quoted names are recognized without changing payload bytes. A new connection's timeout is application-owned: the explicitly labelled numeric millisecond value from that section, or the unchanged 2000 ms default when no timeout was specified. The model's proposed timeout is not used. Ambiguous values or unsupported units require clarification; existing referenced connections remain untouched. Missing explicitly stated independent readback is rejected during that stage, while the shared retry is still available. Trusted task/schema instructions follow the quoted input so the small model can retain the selected target.

Compact HTTP bodies accept a JSON object or a string containing its complete strict JSON encoding. Both decode to the same object and pass the original-field/value and configuration validators. Malformed JSON and scalar bodies fail; no missing braces, values or keys are repaired. This is a wire representation compatibility rule, not permission to invent HTTP bodies.

## Source relationships and review regressions

Connected-device plans additionally bind transport facts to the `(zone, device, action)` relationship in the original request. `AdminSetupSource.h` reads explicit introductions, action values and independent read requirements. It does not generate settings or execute hardware. Sentences, semicolons and list markers are recognized outside quoted strings and JSON; flattening ordinary line breaks does not change the meaning. Quoted names and ordinary Russian inflections are supported. Repeated device names retain their zone; automatically generated connection names include the zone when needed and preserve existing connections.

Merely finding both ON/OFF literals in a device's description is insufficient. The proposed MQTT payload, HTTP body or Modbus value must match its own explicit action. HTTP JSON is compared as an object, so a value belonging to another key cannot authorize an inversion. Readback statements cannot authorize write values. Existing unchanged command mappings can be retained for a scoped edit without inventing a new mapping. Unclear action mappings require clarification.

An existing connection reference must match the requested transport and explicit endpoint, including an HTTP URL's port. Explicit TLS and serial/unit settings are checked. Being present in CATALOG is not authority to choose a different broker. An explicitly requested Modbus read is checked separately from writes, by read function/address/type. A write to the same coil does not satisfy a read requirement.

Explicit device introductions and a stated final device count are checked against the proposed inventory before model stages continue. A successful prefix must not be labelled complete when such a device was omitted. This is a conservative check of explicit source statements, not a claim of understanding every arbitrary prose request. Unsupported or ambiguous descriptions still need clarification and Review.

Every recognized timeout declaration must parse, including a later negative/malformed value after a valid one. A valid occurrence cannot hide a conflicting invalid occurrence. Unrelated topic bytes or timer wording do not declare a timeout. ConfigLoader retains the authoritative numeric range.

The `SetupSourceContract` CTest includes the independent review's counterexamples, flat-text and repeated-name positive controls, explicitly inverse wire mappings, reused matching endpoints, multi-field JSON and temporary ConfigStore/SetupSession tests. Inference is forced and runtime publication is stubbed for isolated Apply; this does not claim a new Qwen/NPU or hardware run.

Stage validation normalizes transport tuples before checking the same source contracts as the final decoder. A repairable command/readback/address error consumes the existing single shared format retry on its own target, before spending inference on later devices.

Modbus writes bind function, zero-based address, wire type and value to the selected write/action, independently of reads and Unit ID. MQTT text observations bind their true/false payloads to the explicitly stated state interpretation, independently of command payloads; intentionally inverse interpretations remain supported. An unchanged previously admitted read mapping may be retained for a QoS-only edit on the same connection.

Numeric source fields require a complete nonnegative integer token; fractional, signed, empty and overflowing fields require clarification, not truncation. Millisecond timeouts may put their numeric value after a colon on the next line. Empty declarations remain declarations and never silently select the default. Explicitly forbidden transports are constraints, rather than extra requested transports; refusing HTTP does not prevent a correctly specified MQTT plan.

Observation-only edits run the same endpoint/transport checks as command bindings. Every proposed Modbus observation is validated against the independent read function/address/type, even when the plan contains no write bindings. Explicitly forbidden read addresses are constraints, not alternative positive addresses. Existing named connection references remain valid; a following setting key such as `topic` is not interpreted as the DNS host of a connection named `Брокер`.

HTTP source URLs are parsed through the complete authority and port token, including when the port appears only inside a URL. Decimal, signed, empty and suffixed URL ports cannot become integer prefixes. Quoted MQTT values retain spaces, Unicode and JSON string escapes both in state-meaning relationships and literal validation. Transport selection separates coordinated predicates (`через MQTT и не использует HTTP`) while retaining shared prohibitions on lists (`HTTP и MQTT не используй`). These checks apply before an accepted draft and are covered through temporary existing-catalog SetupSession/ConfigStore edits as well as creation plans.

Source parsing keeps a comma-separated list under its shared positive or negative predicate; a comma is not by itself a new instruction. Explicit contrasting predicates such as «использует MQTT, а не HTTP» remain separate. The same classification feeds transport selection, Modbus read prohibitions and final coverage: a forbidden address is never a required addition. Quoted payload data is excluded from role, field-name, transport and coverage searches, while its complete bytes remain authoritative for the state mapping.

A QoS-only MQTT observation update may inherit its connection from the catalog without repeating its name or endpoint. This requires the same target, full connection object, fields and MQTT mapping except QoS. Explicit endpoint and transport constraints still run; changing a topic, mapping or connection cannot use the inherited-reference exception. Regression coverage includes shared-list permutations, quoted instruction-like payloads, forbidden/read controls and exact persisted QoS-only diffs.

Quoted mapping keys followed by a colon are parsed as field names, including top-level JSON mapping objects. Their quoted values are consumed as whole tokens, without recursively interpreting JSON-like payload text or nested examples as fields. Conflicting mapping declarations remain errors. Explicit coordinated predicates are separated before comma-list analysis, so a later «а Modbus TCP используй» cannot change the scope of an earlier MQTT/HTTP prohibition.

MQTT QoS is checked against complete labelled integer declarations and explicit prohibitions before draft acceptance, including existing-observation updates. Common QoS and independently stated command/state QoS retain separate scopes. A decimal, signed or suffixed number cannot authorize an integer prefix; unchanged catalog values do not override a different explicitly requested QoS. The authoritative schema still restricts actual QoS to 0/1.

Numeric QoS validation trims whitespace only: source signs, fractions and suffixes survive until strict validation. Structured field extraction preserves an explicit empty value and every distinct duplicate, validates the surrounding JSON object syntax, and never applies prose dash/separator handling to a JSON scalar. A missing field, an empty field and a conflicting duplicate are separate cases.

An introductory mention («измени QoS состояния») may precede a separate labelled value. Explicit delimiters or «на» with a missing RHS remain errors. Explicit «QoS для команд» / «QoS команд» selects command scope even after a state description; state and command settings are verified separately through saved ConfigStore records. Numeric regression tests apply the same signed/empty/fractional tokens to bare, descriptive, JSON-scalar and JSON-string notation.
