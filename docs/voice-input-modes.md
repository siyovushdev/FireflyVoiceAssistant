# Голосовой ввод: слитная фраза или команда после бипа

На странице **Обзор → Слитные команды** находится переключатель
**Разрешить слитные команды**. Изменение сначала попадает в локальный план.
Оно сохраняется и включается обычным **Сохранить и применить → Review →
Подтвердить применение**, без перезапуска процесса.

- Выключено: «Амина» → бип → команда. Речь до окончания бипа и его
  акустического хвоста не является командой.
- Включено: «Амина, включи свет на кухне» можно произнести одной фразой.
  Если продолжения нет, ассистент подаст бип и будет ждать команду.
  В шумной комнате чужая речь может попасть в продолжение; это не
  распознавание личности говорящего.

При смене активной конфигурации незавершённый захват отбрасывается.
Работающие STT/VAD задания завершаются перед повторным использованием,
старый результат не ставится в очередь. Вторая проверка поколения перед
STT/исполнением не позволяет выполнить запись из старой конфигурации.

Настройка — необязательное строго проверяемое поле
`system.voice_input.inline_commands` (boolean) схем 1/2. Если поля нет,
используется CLI `--wake-command-mode after-beep|auto` (по умолчанию
`after-beep`). Отсутствие поля сохраняет старые канонические bytes/hash;
новые предпочтения не меняют F2, пороги KWS, модели или bindings.
Старому executable неизвестно новое поле: для отката сохраняйте весь
предыдущий ConfigStore отдельно; не подменяйте только current поверх
истории с новой схемой.

Экспериментальная CLI опция `--wake-stt-confirmation true` остаётся
отдельной. При её включении фильтр STT проверяет кандидат KWS **в обоих
режимах** до бипа/командного пути. Используются существующие STT и PCM;
слово «Афина» остаётся документированным допустимым вариантом STT.
Фильтр не гарантирует отсутствие всех ложных пробуждений и может
отклонить настоящее обращение при ошибке STT. Повреждённый/неопределённый
префикс не исправляется ради исполнения.

Для слитной речи сохраняются реальные отсчёты во время проверки кандидата
(максимум 3 секунды продолжения), включая начало команды и реальную
паузу, если VAD разделила имя и команду. Общий admission deadline фильтра
остаётся 2 секунды, синхронный ONNX decode не прерывается принудительно:
поздний результат отбрасывается, ресурс передаётся только после join.
Короткий контрольный VAD probe ограничен 4 секундами и не передаёт
синтетическую тишину в STT. Полный исходный текст после снятия только
точного начального wake prefix проходит прежние CommandEngine/SafetyGate.
Текст подтверждения wake никогда не становится командой.

## Проверки

- `WakeFilteredInline`: точный PCM/пауза, команда, начавшаяся после 256 мс
  во время занятого STT, кольцевой буфер, отказ/ошибка/timeout, смена
  поколения, shutdown, повторный бип, исходный текст и отрицательные
  сценарии при намеренно ошибочном ответе модели.
- `VoiceInputHttp`: настоящий ConfigStore/HTTP/RuntimeWorker, Save без
  Apply, горячее переключение, отмена старого поколения **до STT**,
  сохранение F2 и настроек после запуска нового процесса.
- `tests/voice/InlineVoiceChromium.cjs`: настоящий C++ HttpServer,
  Cancel, Review, ровно один Save→Apply на переключение, сохранение
  после reload, CAS conflict, тот же PID, отсутствие исполнений.
- `wake_filtered_replay STT_DIR VAD_MODEL INPUT_JSON REPORT_JSON`:
  явный replay сохранённых mono 16 kHz WAV с настоящими STT/VAD и
  координатами ранее зафиксированного KWS-кандидата (`trigger_block`,
  нумерация блоков по 512 отсчётов с 1). Не открывает микрофон и не
  создаёт исполнителей. Это не повторная оценка качества KWS.
